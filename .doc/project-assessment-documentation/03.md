### 3. Architectural Walkthrough & System Topology

### 3.1 Modular Separation of Concerns

TraceDiary segregates responsibilities across specialized application files to maintain a strict boundary between the data layer and user interface. `scripts.js` is exclusively responsible for presentation logic and event orchestration, utilizing native web APIs to listen for interactions on the DOM. It deliberately defers HTTP network communication to `data.js`, which encapsulates internal state management and REST operations. The generative AI review workflow is also isolated; UI triggers in `scripts.js` delegate execution to `requestAiReview()` (implemented in `ai.js`), which communicates with the backend middleware in `ai-proxy.js`. Finally, structural elements and early visual theme configuration remain confined to `index.html`. This modular architecture ensures view-layer updates do not intermingle with asynchronous data mutations.

```
// scripts.js
entriesList.addEventListener("click", handleListClick);
entriesList.addEventListener("keydown", handleListKeydown);

```

**Evidence:** `scripts.js` → `handleListClick()` / `data.js` → `fetchEntries()` / `ai-proxy.js` → `aiReviewMiddleware()`

### 3.2 Data Model, JSON Schema & Data Dictionary

The application enforces a strict data schema requiring nine standardized fields for every troubleshooting record: `id`, `timestamp`, `category`, `title`, `symptom`, `tried`, `rootCause`, `fix`, and `lesson`. Form ingestion relies on the `FORM_FIELDS` array in `scripts.js` to map these keys, while the `category` attribute is restricted to a specific enumeration defined by `CATEGORY_OPTIONS` in `data.js`. During the creation phase, dynamic payload construction ensures data integrity; rather than trusting client-side inputs for temporal data, the data layer automatically generates an ISO 8601 UTC timestamp before transmission, eliminating localized timezone anomalies.

```
// data.js
async function createEntry(payload) {
  const response = await api.post(API_URL, { 
    ...payload, 
    timestamp: new Date().toISOString(), 
  });

```

**Evidence:** `scripts.js` → `FORM_FIELDS` / `data.js` → `CATEGORY_OPTIONS`, `createEntry()`

### 3.3 Data Layer & State Store Topology (`data.js`)

`data.js` functions as the application's single source of truth, managing a private global array named `entriesState`. External UI components cannot mutate this array directly; they must access it via the `getEntries()` accessor function. To ensure network resilience, the Axios HTTP client is configured with a strict 8-second timeout to prevent infinite hanging states during server failure. Additionally, the network ingestion pipeline implements defensive runtime type guarding. When retrieving data, it explicitly verifies the payload using `Array.isArray(data)`. If the API returns a malformed response, it halts execution and assigns an `unexpectedShape` flag, preventing corruption of the internal store.

```
// data.js
if (!Array.isArray(data)) {
  entriesState = [];
  const shapeError = new Error(`Unexpected response shape`);
  shapeError.unexpectedShape = true;

```

**Evidence:** `data.js` → `entriesState`, `api` (timeout configuration), `getEntries()`, `fetchEntries()`

### 3.4 UI Controller Logic & Rendering Pipeline (`scripts.js`)

The rendering pipeline in `scripts.js` mitigates performance bottlenecks by manipulating cached DOM references rather than executing repeated queries. To avoid the overhead of `innerHTML` string parsing during list updates, `renderEntriesList()` leverages the native `replaceChildren()` method, which swaps the node tree in a single operation. For search functionality, string matching across multiple fields is buffered by a 250-millisecond delay (`SEARCH_DEBOUNCE_MS`), limiting expensive reflows while the user types. Memory overhead is optimized via the Event Delegation pattern; instead of binding unique listeners to every individual entry card, a single listener is attached to the parent `entriesList` container, dynamically resolving event targets via `.closest()`.

```
// scripts.js
function renderEntriesList(entries) {
  // ... maps entries to Node elements
  entriesList.replaceChildren(...cards);
}

```

**Evidence:** `scripts.js` → `SEARCH_DEBOUNCE_MS`, `renderEntriesList()`, `entriesList.addEventListener("click", handleListClick)`

### 3.5 Generative AI Integration & Safe Rendering (`ai.js`)

TraceDiary integrates an external Generative AI SaaS provider for automated log evaluation without compromising system security. The interaction originates in `scripts.js` when the `aiReviewBtn` is triggered, delegating the asynchronous call to `requestAiReview(entry)`. The actual API fetch is proxied through `ai-proxy.js` on the JSON Server backend to securely append the `DEEPSEEK_API_KEY` out of reach of the client browser. To neutralize Cross-Site Scripting (XSS) threats when injecting the AI-generated feedback back into the DOM, the raw response is parsed from Markdown to HTML using `marked.js` and immediately sanitized via `DOMPurify.sanitize()` before being applied to the detailed view element.

```
// scripts.js
aiReviewBtn.addEventListener("click", async () => {
  const entry = findEntryById(activeEntryId);
  // ...
  await requestAiReview(entry);
});

```

**Evidence:** `scripts.js` → `aiReviewBtn.addEventListener()` / `ai-proxy.js` → `requestReview()` / Project Documentation → DeepSeek API Configuration.

### 3.6 REST API & Communication Lifecycle

The system dictates a highly structured end-to-end data lifecycle for CRUD operations. When a user submits the form, `scripts.js` intercepts the native submission, calls `collectEntryFormPayload()`, and validates the inputs via `getMissingFields()`. Upon validation, it dispatches an asynchronous Axios request through `data.js` (either `createEntry` or `updateEntry`) to the `http://localhost:3000/entries` endpoint. Once the mock server successfully processes the request and responds with the canonical object, `data.js` synchronizes the `entriesState` array in memory. Control is then returned to `scripts.js`, which executes `applyFilters()` and updates the UI state, achieving dynamic DOM re-rendering without triggering a full page reload.

```
// scripts.js
const saved = isCreate 
  ? await createEntry(payload) 
  : await updateEntry(editId, payload);
// ...
applyFilters();

```

Evidence: scripts.js → handleEntryFormSubmit(), collectEntryFormPayload() / data.js → createEntry(), updateEntry()
