### 6. Deliverables Checklist & Assessment Readiness

### 6.1 Repository File Structure & Setup

The submitted TraceDiary project repository presents a clean, framework-free architecture that adheres strictly to the module requirements. The core presentation layer is composed of `index.html` (the structural entry point) and `style.css` (custom UI overrides). Client-side logic is securely segregated into specialized functional modules: `scripts.js` handles event orchestration and DOM mutations, `data.js` encapsulates the local state store (`entriesState`) and REST API communications, and `ai.js` coordinates the external Generative AI review workflow. 

The submission includes `package.json`, which defines the `json-server` development dependency required to mock the REST API backend. Finally, the foundational data structure is pre-populated within `data/entries.json`, ensuring the application launches with a realistic dataset matching the defined JSON Schema. 

**Evidence:** `TraceDiary: Project Specification` → `2. Repository & Folder Structure` / `package.json`

### 6.2 Submission Packaging

The project packaging strategy supports both local evaluation and remote cloud environments. The required mock backend is instantiated using the `npm run mock-api` script defined in `package.json`. This command executes `json-server data/entries.json --host 0.0.0.0 --port 3000 --middlewares ./ai-proxy.js`. 

The `--host 0.0.0.0` flag ensures the API remains accessible when forwarded through GitHub Codespaces, satisfying remote evaluation criteria. The inclusion of the `--middlewares ./ai-proxy.js` flag securely attaches the backend proxy required for the Generative AI integration without exposing the `DEEPSEEK_API_KEY` to the client browser. Students submitting the LMS `.zip` archive must ensure the `.env` file (containing the API key) and the `node_modules/` directory are excluded from the package, relying solely on `npm install` for dependency resolution during assessment.

**Evidence:** `TraceDiary: JSON Server Setup` → `Add the npm Script` / `package.json` → `scripts.mock-api`

### 6.3 Oral Assessment Strategy

Candidates preparing for the 15-minute oral defense session must be ready to articulate their architectural decisions and demonstrate mastery over the module's core learning outcomes (LO4–LO12). To verify code ownership, candidates may be asked to explain the application's event-driven architecture (**LO8**), specifically focusing on the Event Delegation pattern utilized in `scripts.js` (`entriesList.addEventListener("click", handleListClick)`), rather than attaching listeners to individual DOM nodes.

Furthermore, students should be prepared to defend their asynchronous state management logic (**LO10**, **LO11**, **LO12**). The examiner may ask how `data.js` handles HTTP timeouts (`axios.create({ timeout: 8000 })`) or how defensive runtime type guarding (`Array.isArray(data)`) prevents application crashes when parsing malformed API responses. Finally, candidates must confidently walk through the Generative AI integration pipeline, explaining how markdown responses are sanitized via DOMPurify before injection to mitigate Cross-Site Scripting (XSS) vulnerabilities.
